1安装插件

两个 jar：NalxerApp.jar 硬依赖 InTheNameOfLinux.jar —— 26.11.11 起 App 的服务端就是直接调 ITNOL 的 API，老版本 ITNOL 缺这些方法会报「服务器没有 ITNOL 插件」，所以两个必须一起换、版本对齐。AuthMe、经济插件、LinuxTeam、LinuxTitle 这些是接上就用，没接就少一块数据，不会报错。

  1. 把 NalxerApp.jar 放进服务器的 plugins/ 目录。服务端用 Paper 或 Spigot 1.12.2，Java 8。
  2. 重启服务器。插件会自己生成配置和密钥，并在 49282 端口把接口开起来（默认监听 0.0.0.0，云服务器要能直连）。
  3. 看控制台的 [联动] 日志，确认 AuthMe、金币、点券、封禁、队伍、头衔都接上了。
  4. 在服务器本机执行 curl http://127.0.0.1:49282/api/health，能返回一串 JSON 就说明接口是活的；在手机浏览器里试 http://你的服务器IP:49282/api/health 能看到同样的 JSON，就说明安全组也放行了。

启动后生成的文件

没有子目录、没有数据库，就这几个文件：

plugins/NalxerApp/
├── config.yml # 全部配置；token.secret 也写在这个文件里
├── stats.yml # 离线玩家的数据缓存（金币 / 点券 / 等级 / 时长）
└── audit.log # 封禁 / 解封 / 登录的审计记录
⚠
默认就是公网直连，明文传输，心里有数就行 插件默认监听 0.0.0.0:49282，手机直接连 http://服务器IP:49282，不需要 Nginx。 代价是密码和令牌在公网上是明文（限流、令牌签名、审计都还在）。想加密有两条路： 前面挂 Nginx（见 Nginx 反代），或者开 http.tls: true 让插件自己上 HTTPS （见本节末尾）。
ℹ️
服务器是离线模式也没关系 登录校验走的是 AuthMe 的账号数据，和正版验证无关。只要玩家在 AuthMe 里注册过，就能用游戏 ID + 游戏密码登录 App。

2配置

全部配置都在一个 config.yml 里，改完执行 /nalxerapp reload 就生效，不用重启服务器。

键默认值说明
http.host0.0.0.0监听地址。0.0.0.0 = 所有网卡（手机才能直连）；只想让本机 Nginx 转发就写 127.0.0.1。
http.port49282接口端口。改了记得同步改 Nginx 里的 proxy_pass，两边要对得上。
http.threads8处理请求的线程数。几十个人的服 8 个足够，没必要往上加。
http.tlsfalse插件自带 HTTPS 的总开关。开了就不用在前面挂 Nginx，地址直接写 https://域名:49282。
http.keystorekeystore.p12证书文件（PKCS12），放在 plugins/NalxerApp/ 下。
http.keystore-password空p12 的密码，开了 tls 就不能留空。
token.secret""令牌签名密钥。留空会自动生成一串随机值写回配置；换掉它等于所有人重新登录一次。
token.ttl-hours168令牌有效期（小时）。168 = 7 天，过期的令牌直接返回 401。
login.require-authmetruetrue = 登录必须通过 AuthMe 校验游戏密码（推荐）；false = 不校验密码，只放行此刻在游戏里在线的玩家，给正版服 / 没装 AuthMe 的服用。关掉它之后，知道别人 ID 的人可以在对方在线时登进去，别在装了 AuthMe 的服上关。
login.attempts-per-minute5每个 IP 每分钟允许几次登录尝试。这是防撞库的第一道闸。
login.requests-per-minute180每个 IP 每分钟允许多少次请求（所有接口合计）。App 自动刷新 30 秒一次，180 有富余。
admin.players[]管理员名单，填游戏 ID。名单里的人能看到玩家管理页；服务器 OP 自动算管理员，不用重复填。
data.*全 true某一项数据要不要对外提供（coins / points / level / playtime / team / title）。关掉哪一项，App 里对应的那一块就显示 —，接口也不返回。
verify.enabledtrue1.4.1 的 Linux 身份验证总开关。开着时，verify.players 里的账号登录 App 后要先输一次 ITNOL 密码，验完才能用其它功能。
verify.players[Linux582021, fs1]哪些账号要二次验证。留空就退回「插件里那个受保护账号」。
su.players[Linux582021, fs1]能碰「命令控制台」和「su（任意命令）」的账号。不在这份名单里的管理员照样能封禁 / 惩罚 / 处理举报 / 管假人，但命令控制台直接返回 403。App 设置里还要再打开「启用 su 控制台」开关才看得见入口。
chat.capture-linktrue26.11.14：把 logs/latest.log 里 [App] 名字: 内容 这种广播收进 App 公屏，标「FS1安卓端」。
chat.link-speakers[app]认哪些方括号前缀是「安卓端发来的聊天」。默认 app（NalxerLink 的广播前缀）；也可以写 fs1、nalxerlink。
features.*全 true1.3.0 起的功能开关：chat / team / titles / checkin / report / penalty / fakes / console。关掉后对应接口直接返回 403，App 里那一页也不再出现。
debugfalse打开后每个请求都往控制台打一行（路径、耗时、来源 IP），排查连不上时用，平时关着。

一份改过的配置长这样

http:
host: 0.0.0.0 # 直连要 0.0.0.0；只走本机 Nginx 就 127.0.0.1
port: 49282
threads: 8
token:
secret: "" # 留空，首次启动自动生成
ttl-hours: 168 # 7 天
login:
require-authme: true
attempts-per-minute: 5
requests-per-minute: 180
admin:
players:
- Linux582021
- Steve

存盘之后执行 /nalxerapp reload。配置写错（缩进错、键名拼错）插件不会崩，会在控制台打一行黄色警告并且继续用旧配置跑。

ℹ️
reload 不会把谁踢下线 只有改了 token.secret，已经发出去的令牌才会立刻失效 —— 因为签名换了，旧令牌验不过。改端口、改限流、改管理员名单都不影响已登录的人。
⚠
token.secret 别提交进 Git 这个密钥是签令牌用的，泄露了别人就能自己伪造一个「已登录」的令牌。仓库里放的是空的 config.yml， 线上那个文件用 .gitignore 排除掉。

3Nginx 反代

直连已经能用（http://服务器IP:49282），这一节是给「想要 https、想要域名」的人准备的：Nginx 转一次，顺便把 http 跳 https 一起做了。

server {
listen 80;
server_name api.nalxer.top;
return 301 https://$host$request_uri;
}
server {
listen 443 ssl http2;
server_name api.nalxer.top;
ssl_certificate /etc/letsencrypt/live/api.nalxer.top/fullchain.pem;
ssl_certificate_key /etc/letsencrypt/live/api.nalxer.top/privkey.pem;
location /api/ {
proxy_pass http://127.0.0.1:49282;
proxy_set_header Host $host;
proxy_set_header X-Real-IP $remote_addr;
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
proxy_set_header X-Forwarded-Proto $scheme;
proxy_read_timeout 15s;
}
}

证书路径按你自己的改，用 certbot --nginx -d api.nalxer.top 签的话它长这样。proxy_pass 后面是纯地址，不要再拼一个 /api/，拼了会把路径再叠一遍，变成 /api/api/login。

改完先 nginx -t 看语法，再 systemctl reload nginx。然后本机验一下： curl -I https://api.nalxer.top/api/health，返回 200 就通了。

⚠
一定要传 X-Real-IP，否则限流会把所有人算成一个 IP 插件看到的来源地址是 Nginx 的 127.0.0.1。少了这一行，全服所有玩家在限流眼里是同一个人： 一个人连续输错 5 次密码，所有人接下来一分钟都登不上，日志里也全是 127.0.0.1，出了问题根本没法查是谁。
ℹ️
前面还有 Cloudflare 怎么办 Nginx 拿到的 $remote_addr 会是 Cloudflare 的节点 IP。要么让 Nginx 认 CF-Connecting-IP， 要么在插件前面就别加这一层 —— 加一层就得配一次真实 IP，多一层就多一个「限流算错人」的机会。

不想挂 Nginx：让插件自己上 HTTPS

服务器上就这一个服务、又懒得维护 Nginx 的话，插件内置了 HTTPS（Java 自带 HttpsServer，没有额外依赖）。 把 certbot 签的证书转成 PKCS12 丢进插件目录就行：

# 1. 证书转 PKCS12
openssl pkcs12 -export -out keystore.p12 \
-inkey /etc/letsencrypt/live/api.nalxer.top/privkey.pem \
-in /etc/letsencrypt/live/api.nalxer.top/fullchain.pem \
-passout pass:你的密码
# 2. 放进插件目录
cp keystore.p12 plugins/NalxerApp/
http:
port: 49282
tls: true
keystore: keystore.p12
keystore-password: '你的密码'

重启后控制台会打 接口已启动：https://0.0.0.0:49282/api/health（插件自带 TLS，证书来自 keystore.p12）， App 里地址填 https://你的域名:49282。

⚠
证书得和域名对得上，用 IP 直连手机不认 自签证书或者「证书是 api.nalxer.top、App 里却填 IP」都会在手机上直接报证书错误。 换证书要重启服务器；tls: true 但 p12 缺失或密码错时，插件打一条警告后退回普通 HTTP，不会起不来。

4接口表

一共 16 个普通接口 + 13 个管理员接口，除了 health 和 login，其它都要在请求头里带 Authorization: Bearer <token>。

方法路径要令牌说明
GET/api/health否返回版本、监听地址和 capabilities（哪些插件接上了）。连不上、数据全是 0，第一个要看的就是它。
POST/api/login否body 传 name + password，校验通过返回 token 和过期时间。
GET/api/me是当前登录玩家的完整数据，App 的「我的」页只靠这个接口。字段见下一节。
GET/api/me?name=Steve是管理员查别人的数据。普通玩家查别人会拿到 403，查自己不带参数就行。
GET/api/online是在线人数和在线玩家名单（名字 + 延迟）。
GET/api/players是在线玩家列表：名字 / 等级 / 延迟 / 世界 / 队伍 / 头衔，最多 200 条。
GET/api/chat?since=0是聊天记录（环形缓冲 120 条），参数 since 是上一条的 id，只回新的。
POST/api/chat是发一条聊天，body：message（最多 200 字）。被禁言会返回 403。
GET/api/team是我的队伍（成员、队长、队标）+ 全部队伍列表。
POST/api/team是队伍操作，body：action（create / join / leave / kick / disband / transfer）+ arg。
GET/api/titles是头衔总览：当前佩戴、已解锁数量、全部头衔 + 解锁条件。
POST/api/titles是佩戴 / 卸下，body：id（传空串是卸下）。
GET/api/checkin是签到状态：今天签没签、连续多少天、累计多少天、下次重置时间（北京时间 0 点）。
POST/api/checkin是签今天的到。返回 reward（5000 金币 / N 点券）；当天重复调用返回 400 和「今天已经签过了」。
GET/api/reports是我提交过的举报 + 处理结果。
POST/api/report是举报别人，body：target / reason。返回举报编号。
GET/api/admin/linux是Linux 系插件清单：名字 / 版本 / 是否运行 / config.yml 大小 / 目录里的文件。需要管理员。
GET/api/admin/linux/config?name=LinuxTAB是读这个插件的 config.yml 原文，App 里直接改。
POST/api/admin/linux/config是保存配置：body {name,text}。先做 YAML 语法检查，过了才写盘 + 重载，旧文件留 config.yml.app-bak。
POST/api/admin/linux/op是启停重载：body {name,op:enable|disable|reload}。
GET/api/admin/status是插件联动状态（11 个插件 + 8 个功能开关），App 设置页那张状态表就是它。
GET/api/admin/players?q=st是在线 + 离线一起搜（离线名字来自 ITNOL 的历史记录），最多 60 条。
GET/api/admin/player?name=Steve是单个玩家详情：数据 + 他身上生效的惩罚 + 举报记录。
GET/api/admin/penalties是当前所有惩罚记录（禁言 / 移动 / 方块 / 封禁）。
POST/api/admin/penalty是op=apply|release，apply 传 type / name / minutes / reason。
GET/api/admin/reports?pending=1是举报列表，pending=1 只看没处理的。
POST/api/admin/report是处理举报：op=accept|reject + id + note。
GET/api/admin/fakes是假人列表：名字 / UUID / 世界 / 是否活跃 / 坐标。
POST/api/admin/fake是op=add|remove。召唤要求本人正在游戏里（假人要站在你脚下）。
GET/api/admin/commands是命令白名单 + 分组清单，App 的「服务器命令」页靠它渲染。
POST/api/admin/exec是执行一条白名单命令，body：command。返回真实回显，最多 40 行。
POST/api/admin/su是1.7.0 的 su：验证过 Linux 身份后执行任意命令（不走白名单，stop / restart 仍然拦），body：command。
GET/api/admin/search?q=st是按名字模糊搜玩家，最多 30 条，每条带 name / online / banned。需要管理员。
GET/api/admin/bans是当前生效的封禁列表，带原因和到期时间。需要管理员。
POST/api/admin/ban是封禁，body：name / reason / minutes。需要管理员。
POST/api/admin/unban是解封，body：name。需要管理员。

5数据字段

/api/me 返回一个 JSON 对象，App 的每一块显示都对应其中几个。下面挑常用的写，加粗的是 1.2.0 新增的。

字段类型说明
namestring游戏 ID，就是登录时填的那个名字。
uuidstring玩家 UUID，带连字符的完整形式。
onlineboolean现在是否在线。离线也能拿到数据，只是这个字段是 false。
coinsnumber金币数量。没装经济插件时是 0，要靠 hasCoins 判断该不该显示。
hasCoinsboolean服务端有没有接上金币来源。false 时 App 显示「—」而不是 0。
pointsnumber点券数量，同理。
hasPointsboolean服务端有没有接上点券来源。
levelnumber玩家等级。1.2.0 起离线时也读真实存档（world/playerdata/<uuid>.dat 的 NBT），不再是 0。
expnumber当前这一级已经攒的经验，用于画进度条。
totalExpnumber从 0 级算起的总经验，不掉级就只增不减。
levelLivenumber实时等级，含经验条上那点还没存盘的进度。
expIntoLevelnumber当前这一级已经攒的经验（和 exp 同义，App 用它算进度百分比）。
expToNextnumber升到下一级要多少经验（1.12.2 公式：2L+7 / 5L-38 / 9L-158）。
identityobject玩家身份（来自 XlandCore）：{role, label, prefix, roles, hasXland}，label 是「服主 / 副服主 / 市长 / 协管 / 管理员 / 普通玩家」。
rolestring上面那个 label 的简写，省得 App 再拆一层。
teamTagstring队伍标识（队标）带色码，没队伍是空串。
titleId / titleNamestring头衔 id 和干净名字，没戴头衔是空串。
mutedboolean是否被 ITNOL 禁言（App 发聊天前会看它）。
health / maxHealth / foodnumber在线时的生命、血量上限、饥饿值。
gamemode / world / pingstring / string / number游戏模式、所在世界、延迟（毫秒）。
banUntilnumber封禁到期时间戳（毫秒），永久封禁是 0。
playtimeHoursnumber累计在线小时数，保留一位小数。
firstPlayedstring第一次进服时间，ISO 8601 格式。
lastPlayedstring最近一次进服时间，同样 ISO 8601。
teamstringLinuxTeam 队伍名。没队伍是空字符串，App 显示「无队伍」。
titlestringLinuxTitle 头衔。没头衔是空字符串。
bannedboolean当前是否处于封禁状态。被封的人也能登录 App 看自己的状态。
banReasonstring封禁原因。没封禁是空字符串。
ℹ️
离线为什么也能看到等级 1.2.0 起离线玩家的等级直接从 world/playerdata/<uuid>.dat 的 NBT 里读， 不再依赖「上次有人在线时缓存下来的值」，所以挂机号、退服很久的人也能看到真实等级。levelLive 只是标记这次读数是不是实时的。
⚠
别拿 coins: 0 直接当「没钱」 判断有没有这个数据源看 hasCoins。只读 coins 的话，没装经济插件的服务器上每个人看起来都是穷光蛋。

每日签到

「我的」页顶部那张卡就是签到：点一下领奖励，50% 是 5000 金币，剩下的是 1–5 点券。 每天北京时间 0 点重置。

  • 连续签到天数会累加，断一天就从 1 重新算；累计天数永远只增不减。
  • 当天签过按钮变「已签到」，再点会被服务端挡回来（`400`）。
  • 奖励真的进游戏账户，下线也算数 —— 走的是 Vault 和 PlayerPoints。

装到手机上

两个平台给的包不一样，别装错：

平台文件怎么装

⚠

「我的」页看什么

从上到下一屏：在线状态 → 金币 / 点券 / 等级三张卡 → 经验进度条 → 队伍和头衔 → 累计在线时长和最近一次上线时间。 被封禁的账号在最上面多一条红色横幅，写着原因和到期时间。

「聊天」页怎么用

游戏里公屏说的每句话都会同步到这里（带 · 游戏 标记），在 App 里发的消息会以 [LinuxAPP] 你的名字：内容 的格式广播回服务器，游戏里的人能看见。30 秒自动拉一次新消息，有未读时底部页签上会出现小红点。

队伍频道（1.4.0）

聊天页顶部有「世界 / 队伍」两个小按钮。点「队伍」就只看队内消息：发出去的话只有队友看得到，游戏里也会以 [队伍] 队标 名字 » 内容 的样子出现。

  • 一个人在几个队里时，队伍频道下面会多出一排队名，点哪个看哪个、发到哪个。
  • 队伍管理也在这一页：成员、贡献、退出、踢人、转让、解散、建队、加入，都在聊天记录下面。
  • 队长把队伍聊天关了（/team setting chat off），App 这边发会被挡回来。

发不出去通常就两个原因：被 ITNOL 禁言了（返回「你被禁言了，现在不能在服务器说话」），或者单条超过 200 字。

ℹ️
控制台 / RCON 的 say 也会进来（1.3.1） 服务器控制台敲 say 今晚八点维护、面板用 RCON 发播报，都会以「控制台」的身份出现在聊天里。 万一你那边的面板走的是别的派发方式，插件还会盯 logs/latest.log 里 [Server] / [Rcon] / [CONSOLE] 开头的播报行兜底 （chat.capture-log，默认开）。同一句话不会重复出现。

FS1 安卓端（NalxerLink）发的消息也能看见（26.11.14）

如果服务器上装了 NalxerLink（给安卓客户端用的登录 / 聊天接口），那边发的聊天会以 [App] 用户名: 内容 的形式广播到控制台。这里的用户名就是对方在 FS1 安卓客户端登录时 填的那个账号（比如 Linux582021），不是固定的「FS1玩家」字样。NalxerApp 会把这行认出来， 原样用这个用户名进 App 的「世界」频道，后面标 · FS1安卓端——一眼能分清是 游戏里 说的、 NalxerApp 发的、还是 FS1 安卓端 发的。显示形如：Linux582021 · 23:59 · FS1安卓端。

  • 开关：chat.capture-link，默认 true；关掉就不再读这类广播。
  • 前缀名单：chat.link-speakers，默认 [app]。别的客户端广播前缀不是 [App] 的话，把它加进这个列表。
  • 实现方式：只读 logs/latest.log，不碰 NalxerLink 本身，那个插件怎么升级都行。

在 App 里管 Linux 系插件（1.7.0）

设置页最下面一张「Linux 系插件」卡，点进去就是列表：每个插件一行，写清楚版本、有没有 config.yml、目录里还有哪些文件。

  • 停用 / 启用：直接 disablePlugin，停用后服务器立刻不再跑它（被别的插件依赖会失败并告诉你）。
  • 重载配置：等于 reloadConfig()。
  • 改配置：把 config.yml 原文读出来，在手机上改完点「保存并重载」。保存前先跑一遍 YAML 语法检查，写错了不落盘、原文还能继续改；成功会留一份 config.yml.app-bak。
列的是自家插件：名字以 Linux 开头的（LinuxACE / LinuxChestGUI / LinuxSync / LinuxTAB / LinuxTeam / LinuxTitle）加上假人插件 FakePlayerPlugin；插件联动状态那张表也只显示这些。

「队伍」页怎么用

没队伍时给的是「建队」按钮和全服队伍列表，点一个就能申请加入；有队伍时显示队长、队标、成员（在线的人名是亮的），队长能踢人 / 转让 / 解散，队员只能退出。所有操作直接调 LinuxTeam，和游戏里 /team 命令是同一套数据。

ℹ️
队伍操作要人先进服 LinuxTeam 的部分操作需要在线玩家对象，人在线时最好用。离线时点建队会提示「队伍操作要先进服」，这是正常的。
ℹ️
一个人可以在好几个队里（1.3.1） LinuxTeam 支持多队，App 现在按「我所在的全部队伍」一张张列出来，每张卡有自己的退出 / 解散按钮。

「头衔」页怎么用

顶上是你现在戴的头衔（右边有「卸下」），下面是全部头衔和它们的解锁条件 —— 条件都翻成了人话：「今日在线 12 小时」「挖矿 99999 次」「管理员发放」「节日活动」。已解锁的点一下就能戴上，进服或重新进服后会在名字前面显示。

ℹ️
离线也能看到自己戴的头衔（1.3.1） 以前这块要走玩家对象，人不在线就读不出来 —— 明明戴着却显示「没有」。 现在直接读 LinuxTitle 的存档（active id + titles.yml），离线也在。 另外解锁判断统一按小写比，titles.yml 里 id 写成大写也认。

管理页怎么封人

只有 admin.players 名单里的人或者 OP 才看得到这个入口。流程是五步，一步都不能少：

  1. 进管理页，在搜索框里打一部分名字（打 st 就能搜到 Steve），等结果出来。
  2. 点一下要处理的那个玩家，选中之后底部才会亮出操作栏。
  3. 点「封禁」，填原因 —— 这一栏建议写清楚，玩家在 App 里看到的就是它。
  4. 选时长：1 小时 / 1 天 / 7 天 / 30 天 / 永久。
  5. 再点一次「确认封禁」。在线的人会被当场踢下线，封禁立刻生效，同时写一条审计日志。

解封在同一个页面：admin/bans 列表里点开那条封禁，点「解封」就行，不用填原因。

装 ipa 报「Application is missing the application-identifier entitlement」

  • 这句话的意思是：这个包装进去的时候没有带 application-identifier 这个授权项，不是包坏了，是「没签名 / 签名没注入授权」。
  • 三条路，任选一条：
    · 先签名再装：全能签里不要点「安装」，走「签名」→ 选证书 → 签完再装；
    · 用电脑签：Sideloadly / AltStore 登 Apple ID 重签，最稳；
    · 直接用 ad-hoc 版：下载页那两个「装不上？用 ad-hoc 版」，包里已经用 codesign --sign - 写入了 application-identifier 与 _CodeSignature，TrollStore 这类只认授权的安装器可以直接装。
  • ad-hoc 版没有开发者证书，越狱/TrollStore 之外的普通机器仍然要用证书重签一次才能启动，这点和未签名版一样。
  • 如果重签后还是报同样的错，换一个 Bundle ID（比如 top.nalxer.app2）再签，多半是和已装的旧包冲突。

26.12.2 登录页「测试连接」：自己签名的 App 连不上时先看这里

  • 登录按钮下面多了一个「测试连接」，只请求 /api/health，不用账号密码。
  • 成功会显示 HTTP 200，服务端版本 x.y.z；失败会把原始错误原样贴出来。
  • 常见三种原因会自动附上建议：
    · ATS：重签名工具（全能签等）重写了 Info.plist，把 http 访问拦掉了 —— 重签时不要勾「修改 Info.plist」，或换回我们给的未签名 ipa 再签；
    · Load failed：先在 Safari 打开同一个地址，能看到 JSON 就说明网络没问题、是签名包被限制了 http；
    · 超时：地址写错、端口没放行、或服务器只在内网。
  • iOS 端 Info.plist 补了 NSLocalNetworkUsageDescription 与 NSBonjourServices，连局域网服务器时会弹权限说明。

8服务器命令（管理员）

管理员在 App 的管理页会多一个「服务器命令」标签。它不是给玩家看的榜单，而是一个受控的命令执行器： 点一条命令 → 参数自动填进输入框 → 服务器主线程执行 → 回显原样贴回来。

这样做的好处是 ITNOL 的 /linux xxx、LinuxTAB 的 /ltab、/team、/title、 /fp 全都能用，插件以后加新子命令也不用改 App。

  • 先选分组：封禁与解封 / 查人 / 服务器 / Linux 系插件，四个分组覆盖日常操作。
  • 点一条：命令根和参数占位符会填进下面的输入框，比如 linux ban <玩家> [原因]。
  • 补完参数，点「执行」（或直接按回车）。
  • 看回显：下面是服务器真实的输出，分页、配色都已经被剥掉，只剩文字。

    • 默认能用哪些命令

    白名单在 admin.commands.allow，默认这些根命令：

    根命令干什么例子
    linuxITNOL 总入口：封禁、查人、插件状态、审计、日志linux plugins、linux lookup Steve
    tempban / unban临时封禁 / 解封（linux ban 没有时间参数，定时要用 tempban）tempban Steve 7d 刷屏
    banip / unbanip封 IP（小号报复时用，注意别把网吧 / 学校网段封了）banip Steve
    banlist看全部封禁记录，分页banlist 2
    ltab / lchestLinuxTAB 状态与刷新 / 箱子面板ltab info
    title / team头衔 / 队伍插件title help
    fp / fplist / fpr / fpsave / fpreload假人插件的增删查、重载、存盘fplist
    linuxsync / nalxerapp玩家数据同步 / 本插件自己的状态与重载nalxerapp status

    要放开别的根命令，往 admin.commands.allow 里加一行，然后 /nalxerapp reload：

    admin:
    commands:
    enabled: true
    allow: [linux, banlist, unban, tempban, ltab, team, title, fp]
    # 只写根命令，不带斜杠；子命令不受限

    永远执行不了的命令

    下面这些在代码里写死，改配置也放不开：

    命令为什么锁死
    stop restart reload一键把服务器关掉或重载，手滑一次全服掉线
    op deop whitelist permissions提权类，等于把服务器送给别人
    give gamemode gm刷物品 / 改模式，会直接毁经济
    kick plugins version sudo踢人、暴露插件列表、代执行任意命令
    ⚠
    执行前会再问一次 标了「谨慎」的命令（封禁、封 IP 这类），点执行时 App 会弹一次确认框，把命令原文念一遍。 手指滑到就执行的年代已经过去了。

    边界与超时

    每条命令最多等 5 秒，回显最多 40 行 / 4000 字，超了就截断 —— 防止有人拿 banlist 一口气翻几百页把 App 卡死。

    命令在服务器主线程执行，和你在控制台敲是一样的效果；执行记录会写进控制台和 audit.log：

    2026-11-03 01:44:02 Linux582021 控制台执行 ltab info
    2026-11-03 01:44:15 Linux582021 控制台执行 tempban Steve 7d 刷屏
    💡
    命令现在是管理页里的一个子标签 1.4.0 起底栏没有单独的「命令」了，进「管理 → 命令」；白名单、危险命令二次确认这些规则没变。

    Linux 身份验证（1.4.1）

    verify.players 里的账号（默认就是 ITNOL 那个受保护号 Linux582021）登录 App 后，会先弹一个密码框： 「你登陆的是 Linux582021 账号，请通过 Linux 身份验证」。输的是 ITNOL 的验证密码，不是游戏密码。

    • 验证之前，除了 /api/me 和退出登录，其它接口一律 403 need_verify，界面上什么都点不动。
    • 验证状态跟着令牌走，重开 App 不用再验一次；令牌过期或换设备要重验。
    • 连错 5 次锁 10 分钟，服务端 audit.log 里有记录。

    su 控制台（1.7.0）

    「管理 → 命令」最上面那张卡。验证过 Linux 身份之后，可以在弹窗里输入任意命令，不再受 admin.commands.allow 白名单限制 —— 给东西、传送、改权限、装插件都行。

    • 只拦 stop / restart / end：这三条按下去服务器就没了，App 里补救不了。
    • 每条都写 audit.log，格式 X su 执行 命令。
    • 回显里要是「错误 / 找不到 / Unknown command」，App 会直接标红说失败，不会假装成功。

    假人逐个开关（1.4.1）

    假人列表每个名字下面会标「区块已加载 / 没加载」「会刷怪 / 不刷怪」，右边四个按钮：

    • 停载区块 / 加载区块 —— 对应 FakePlayerPlugin 的区块常驻（keep-loaded-chunks）；
    • 关刷怪 / 开刷怪 —— 对应 spawn.*，假人站着的地方刷不刷怪；
    • 重生（按新设置重新出现）、移除。

    举报能看已处理（1.4.1）

    举报子页分「待处理 / 已处理」两个标签，已处理的会显示处理结果（受理 / 驳回）、处理人和备注。 接口是 GET /api/admin/reports?pending=0，返回里带 count / handledCount / pendingCount。

    💡
    命令页要重新登录才出现 刚被加进 admin.players 的人，手上的令牌还是普通令牌；让他在设置页退出登录再登一次，管理页和命令标签才会出来。

    9常见问题

    下面这几条覆盖了绝大多数「打不开 / 数据不对」的情况，按顺序试。

    登录提示「游戏密码不对」
    App 校验的是 AuthMe 的密码，不是论坛密码、不是邮箱密码。先在游戏里 /login 密码 确认这个密码是对的。
    还是不对的话按顺序查：① 玩家在 AuthMe 里注册过没有（plugins/AuthMe/ 里能不能找到这个 ID）；② 大小写有没有打错，ID 是区分大小写的；③ 服务器是不是把 login.require-authme 改成了 false —— 关掉后不再校验密码，只放行在线玩家，离线时怎么登都失败。
    另外注意限流：一分钟内输错 5 次会返回 429，这时候密码是对的也登不上，等一分钟再试。
    数据全是 0，或者显示成「—」
    「—」表示服务端根本没接上那一项数据源，不是你的数据丢了。用浏览器打开 https://api.nalxer.top/api/health，里面有一个 capabilities 字段，写着每一项接没接上：
    coins: false → 服务器没装经济插件，或者装了但插件名不在 data.* 的识别列表里；
    points: false → 点券插件没接上；
    team: false / title: false → LinuxTeam / LinuxTitle 没装。
    而如果显示的是 0 而不是「—」，说明数据源接上了，只是这个玩家确实没有：新号、或者数据存在别的插件里。
    离线玩家的金币显示 0
    经济插件一般把余额存在内存里，玩家下线才写盘，有的干脆只对在线玩家提供查询接口。插件能做的只有两件事：在线时直接问经济插件要，离线时读它落盘的数据。
    插件已经做了能做的：玩家在线时把金币记进 plugins/NalxerApp/stats.yml，离线后读这份缓存显示，所以一般不会是 0。但如果那个玩家从没在线过一次、或者换了经济插件导致旧缓存对不上，就只能是 0 —— 这不是 App 的问题。
    另外新人第一次进服之前没有任何数据，显示 0 是正常的。
    手机连不上，浏览器打开 http://服务器IP:49282/api/health 也打不开
    先分清是哪一层不通：本机 / 安全组 / App 填的地址。
    ① 服务器本机 curl http://127.0.0.1:49282/api/health 不通 → 插件没起来、端口被占，或者 config.yml 的 http.host 被改成了别的网卡，看一眼启动日志；老版本默认是 127.0.0.1:8787（只监听本机），新 jar 会自动改成 0.0.0.0:49282，日志里有一行「已自动改成」；
    ② 本机通、手机浏览器打 http://服务器IP:49282/api/health 不通 → 云服务器安全组 / 系统防火墙没放行 49282，去控制台加一条入站规则（TCP 49282）；
    ③ 浏览器能打开、App 连不上 → App 里的地址填错了：忘了端口、多写了 /api、或者末尾多了斜杠。设置页的「测试连接」会直接告诉你通没通、联动接没接上。
    走 https://api.nalxer.top 域名的话，还要确认 Nginx 反代指向 127.0.0.1:49282、证书没过期（nginx -t，再看 /var/log/nginx/error.log）。
    服务器换了地址 / 换了域名，App 怎么改
    进 App 的设置页，「接口地址」那一栏直接改成新的 https:// 地址，保存后会要求重新登录一次（旧域名发的令牌不作数）。
    如果连 App 的登录页都进不去（老地址已经彻底不能用了），在登录页也能找到「修改接口地址」的入口。这个地址是存在手机本地的，卸载重装会清掉，等于回到第一次打开的状态。
    管理员在管理页搜不到某个玩家
    搜索走的是服务器上记录的玩家数据，从来没进过服的名字搜不到，这是正常的。
    另外两种可能：① 你手上的令牌是加进 admin.players 之前登录的，重新登录一次才会带上管理员身份；② 名字打错了 —— 搜索是模糊匹配但区分大小写，试试只打前三个字母。

    10安全说明

    这一节说清楚：密码去了哪、令牌怎么算的、什么样的部署方式等于没设防。

    密码

    App 里输入的密码，只在登录那一次请求里出现一次。插件拿到之后立刻交给 AuthMe 校验，校验完就丢掉 —— 不写配置文件、不写日志、不存数据库。所以别人拿到服务器上的文件，也翻不到任何人的密码。

    令牌

    登录成功后发的是 HMAC 签名令牌，签名的密钥就是 token.secret。令牌里带着玩家名和过期时间， 服务端每次校验都重新算一次签名，对不上就直接 401。默认有效期 7 天（168 小时），改密钥等于让所有令牌立刻作废。

    限流

    每个 IP 每分钟 5 次登录尝试 / 180 次请求。前者挡撞库，后者挡脚本刷接口。 这两个数字都按 IP 算，所以 Nginx 那一行 X-Real-IP 是硬要求 —— 少了它，全服共用 127.0.0.1 这一个额度。

    监听与审计

    接口默认监听 0.0.0.0:49282，公网可以直接连（明文 HTTP）。想加密就挂 Nginx 或开插件自带 TLS； 安全组里也可以只放行自己常用的网段。所有封禁 / 解封都写进 plugins/NalxerApp/audit.log，谁在什么时候封了谁、什么原因、多长时间，一行一条。

    ⚠
    别用明文 HTTP 暴露这个接口 密码是在请求体里传的，走 http:// 等于把每个人的游戏密码写在明信片上寄出去。 一定要 HTTPS，证书用 Let's Encrypt 免费签就行。安卓 9 以后默认也禁止明文 HTTP，这条路本来就走不通。
    ℹ️
    被限流挡住的时候怎么办 等一分钟。限流是按 IP 的滑动窗口算的，不会因为你重开 App 就重置。 如果是整栋楼共用出口 IP（学校、网吧、公司 NAT），确实可能出现「别人试错把我锁了」的情况 —— 这种环境只能把 login.attempts-per-minute 调大，或者干脆别在公共网络里登。
