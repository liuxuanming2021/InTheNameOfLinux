STRENGTH

七档检测强度

一条命令切换松紧

级别中文阈值倍率容忍倍率适用场景
Lowest最宽松×1.35×2.0误报几乎为零，明显作弊也会放过一部分
Low宽松×1.20×1.6客户端差异大、插件多的服务器
Medium中等×1.10×1.3比推荐值再松一点
Pro推荐×1.00×1.0默认值，抗误报优先
High严格×0.95×0.75开始能抓小动作，误报风险上升
Max很严格×0.90×0.60只建议无延迟、无特殊插件的纯净服
Highest最严格×0.85×0.45极易误报，仅测试或自建纯净服

切换：/ace strength High —— 会写回 config.yml 并立刻生效。

CONFIG

配置文件

plugins/LinuxACE/config.yml

enabled: true
prefix: '&8[&bLinuxACE&8] &r'
debug: false

# 检测强度：Lowest / Low / Medium / Pro / High / Max / Highest
strength: Pro

risk:
  kick-at: 20          # 危险等级达到多少踢出（只踢，不封）
  decay-seconds: 45    # 多少秒没新违规就掉 1 点
  min-tps: 15.0        # TPS 低于此值整体暂停检测

alert:
  use-permission: true
  permission: linuxace.alert
  cooldown-seconds: 10 # 同一玩家同一检查的告警冷却
  console: true

exempt:
  bypass-node: linuxace.bypass
  ops: true            # OP 完全不检测（/ace ops off 可关）
  creative: true
  allow-flight: true
  worlds:
    - spawn_build

# 延迟补偿（与插件无关，只看玩家实测 ping）
lag-compensation:
  enabled: true
  base-ping: 80
  per-100ms: 0.25
  max-grace: 1.5

compat:
  auto-disable: true   # 检测到冲突插件时自动关闭对应检查
  eagler-grace: 0.50   # 只有检测到 EaglerXServer 才加
  via-grace: 0.20      # 只有检测到 ViaVersion 才加

checks:
  fly:
    enabled: true      # 关掉就是真的不检测
    tolerance: 4
    risk: 4
    max-air-ticks: 40
  # … 其余 21 项同理

重要：没检测到对应插件时，所有放宽一律是中性值 （倍率 1.0、检查照常），代码里留着兼容分支也不会让它变松。 用 /ace status 的「放宽门控」一行可以直接看到当前实际放宽量。

误报了怎么办

先别急着关掉整个插件。按这个顺序处理，通常一两步就能解决：

1. /ace check <玩家> 看是哪一项在报。
2. 把那一项的 tolerance 调大（比如 3 → 6）， 只放宽这一项，不影响其它检测。
3. 如果整类都在报，把 /ace strength 降一档。
4. 确认是插件冲突导致的，把冲突插件加进兼容判断。

  • 只调单项，别整体降
    tolerance 调大比降强度精准得多
  • 先看 /ace logs
    能看到最近的告警与触发原因
  • 临时豁免
    /ace exempt <玩家> 给特定人开白名单
  • OP 默认不检测
    管理员自己测试不会被踢

DEPENDENCY

前置依赖

LinuxACE 依赖 InTheNameOfLinux

InTheNameOfLinux 是 LinuxACE 的硬依赖：没装它、或它被禁用时， LinuxACE 不会启动（Bukkit 层面直接拦住）。

封禁统一走 ITNOL 的封禁体系 —— 记录、历史、审计日志、到期解封任务都由它生成； /ace ban 的封禁会出现在 /linux lookup 里。 反过来 ITNOL 可以单独运行，依赖是单向的。

装了 ITNOL 之后还能用 /ace lookup <玩家>， 一次看到封禁历史与反作弊记录。
