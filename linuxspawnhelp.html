1快速开始

LinuxSpawn 只改一件事：原版刷怪的频率。它把世界的 ticksPerMonsterSpawns / ticksPerAnimalSpawns 置 0，让原版那次调用直接返回， 然后每 tick 自己调用同一个 SpawnerCreature.a(...)。位置、群系、光照、地表、 世界边界、玩家距离、生物上限、CreatureSpawnEvent 全部还是原版代码在判断。

安装

  1. 把 LinuxSpawn.jar 放进 plugins/，重启服务器。
  2. 控制台出现 [LinuxSpawn] 已接管世界 world 就说明生效了。
  3. 进游戏执行 /spawnrate list 看每个世界的倍率。

只支持 1.12.2（v1_12_R1）。它直接调用 NMS 的 SpawnerCreature， 其他版本类签名不同，启动会直接停用自己。

三个最常用的操作

/spawnrate set world monster 2      # 生存世界怪物 2 倍
/spawnrate set world creature 0    # 动物不刷
/spawnrate stats                   # 看每秒循环数与单轮耗时

2命令详解

主命令 /spawnrate，别名 /sprate；权限 spawnrate.admin（默认 OP）。

命令说明
/spawnrate list列出所有世界的接管状态、四类倍率和玩家数
/spawnrate stats每秒原版循环数、每秒生成数、单轮耗时、当前 TPS
/spawnrate set <世界> <类别> <倍率>类别：monster / creature / water-creature / ambient；倍率 0~1000，写回 config.yml 并立即生效
/spawnrate clean [世界|*] [类别|all] [半径|all] [dry]分批清理自然怪物；dry 只统计不删
/spawnrate reload重读 config.yml（保留注释，不会被格式化掉）

倍率是怎么算的

原版怪物每 tick 跑一次、动物每 400 tick 跑一次；倍率 1 就是原版，2 就是每 tick 跑两轮， 0.5 就是隔一 tick 跑一轮。动物类别实际周期是 lcm(动物周期, 400)，所以倍率会按这个基准折算。 一轮的循环次数上限由 max-cycles-per-tick（默认 8）截断，防止某个世界一口气跑太多。

3配置文件全键

文件：plugins/LinuxSpawn/config.yml。改完 /spawnrate reload 即可，不用重启。

4卡服分析与 26.11.18 加固

结论：不会比原版更卡。它调的是原版同一个 SpawnerCreature，一轮的耗时和原版完全一样 （测试服实测单轮 0.24 ms）；倍率只是让这一 tick 多跑几轮，而且有 max-cycles-per-tick 截断。 真正需要防的是清理和每 tick 的杂项开销，26.11.18 把这些都改了：

位置改之前改之后
世界列表每 tick 复制一份 Bukkit.getWorlds()缓存 20 tick
doMobSpawning每 tick 读 gamerule 并解析字符串缓存 20 tick
清理半径每只实体 new 一个 Location直接用 NMS 坐标算平方距离
清理执行单 tick 遍历并删除全部命中实体每 tick 最多 250 只 / 4 ms
刷怪笼标记每次生成都写一遍 NBT已有 tag 就跳过
TPS 保护没有低于 15 自动暂停，恢复后继续

压测数据（测试服，Paper 1.12.2）

  • 倍率 1：约 20 次循环 / 秒，单轮 0.24 ms，TPS 19.9。
  • 倍率 5：循环数升到窗口均值 35.7 次 / 秒（60 秒窗口被前段 1 倍稀释，即时值约 100）， 生成数仍是 1.4 只 / 秒 —— 因为 mobcap 已满，说明上限还是原版在管。
  • 整个过程 TPS 19.86，恢复倍率后 19.87。

5和 LinuxAPP 联动

服务端装了 LinuxAPP（26.13.56 起）后，启动日志会出现：

[LinuxAPP] [联动] 已接上 LinuxSpawn 刷怪（状态 / 倍率 / 清理）

手机 App（iOS 13+ 原生界面）的「管理」页会多一个刷怪页签：

  • 总览：接管状态、当前 TPS、单 tick 上限、低 TPS 保护阈值、自动清理剩余时间。
  • 每个世界一节：怪物 / 动物 / 水生 / 环境四类倍率，点一下就能改。
  • 操作：清理这个世界的自然怪物、全部世界各清一次、让 LinuxSpawn 重读 config.yml。

底层接口（也可以自己写脚本调）：

接口说明
GET /api/admin/spawn返回 {ok, available, data:{enabled,tps,safety…,worlds:[…]}}
POST /api/admin/spawn {"action":"set","world":"world","category":"monster","value":2}改倍率
POST /api/admin/spawn {"action":"clean","world":"world"}分批清理
POST /api/admin/spawn {"action":"reload"}重读配置

LinuxSpawn 没装时，GET /api/admin/spawn 返回 available:false， App 里那个页签也会自动隐藏。

6和 InTheNameOfLinux 联动（26.11.18）

缺 ITNOL 时自动降级、不报错；装了就用上这三条：

能力说明
审计改倍率 / 清理 / 重载写一条 ITNOL 审计（类型「刷怪」），落在 plugins/InTheNameOfLinux/audit.yml
协管可用除了 spawnrate.admin，ITNOL 的协管（xlcore.mod）也能执行 /spawnrate
状态显示/linux logs 第 4 页「子插件联动」显示 LinuxSpawn 接管的世界数与 TPS

启动日志会打印：[LinuxSpawn] [联动] 已接上 InTheNameOfLinux（审计 + 协管可用命令）。 ITNOL 比本插件晚 enable，审计入口会在第一次写审计时再取一次，不会因为加载顺序丢记录。

7常见问题

调了倍率但怪物没变多？

先看 /spawnrate stats：循环数上升但生成数不变，说明是 mobcap 满了 —— 这时候该清怪或调 spawn-limits，而不是继续加倍率。

生存世界怪太少 / 太多，人少的时候卡？

把倍率单独给那个世界设，或者用 safety.min-tps 让低 TPS 时自动停。

刷怪笼会受影响吗？

不会。刷怪笼是 TileEntityMobSpawner 自己 tick，LinuxSpawn 完全不碰； 它产出的怪还会被清理器保护（protect-from-mob-spawner）。

清理会不会把我养的动物清了？

默认类别只有 monster；而且命名、驯服、拴绳、无敌、刷怪笼产物都不清。 想连动物一起清就加类别 creature，但建议保留 protect-tamed。

能卸载吗？

直接删 jar 重启即可，onDisable 会把两个计数器还原成原版值，不会留下被接管的世界。

多人同时改倍率会冲突吗？

每次 set 都会重写 config.yml 并 reload；两个人同时改不同世界没问题，改同一个值以最后一次为准。
