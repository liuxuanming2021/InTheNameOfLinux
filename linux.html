26.11.4正式版 更新亮点

本版集中在物品安全与信息可读性： 把独立的 BanNbt 插件整体合并进来，查询能直接给出维度坐标， 主页与帮助页改为点击即执行。

🧪 非法 NBT 物品检测（合并 BanNbt）

原 BanNbt 插件的功能整体并入本插件， 现在只需装一个插件、维护一份配置。

  • 检测超限附魔等级、非法属性修饰符
  • 抗性提升等级 ≥ 4 自动压回 3 级
  • 周期扫描（默认 20 秒）或手动 /linux nbtview
  • 清除时播报带悬浮详情：物品名、数量、原因
豁免名单
  • nbt.exempt-players — 按玩家名豁免
  • nbt.exempt-worlds — 按世界豁免

不含任何硬编码玩家名，全部写进配置文件。 OP 不自动豁免，需要显式写进名单。

📍 查询显示维度与坐标

/linux lookup 现在会给出玩家所在维度与精确坐标。 在线玩家实时读取当前位置；离线玩家使用退出服务器时记录的位置； 拿不到时明确显示「无法获取」，不会给出错误坐标。

本版其它改动
  • 主页改为点击即执行 — /linux plugins 等一键跳转
  • 配置不再「看不见」 — 缺失项自动补全并写回
  • 管理层列表读真实配置 — 与配置同步，不再写死
  • 查看即同步 — 查询时顺带刷新缓存

核心功能

从身份验证到物品安全，八个模块覆盖服务器日常管理的主要环节。

🔐 身份验证

聊天栏输密码，服务端日志零痕迹。

  • 密码最短 6 位
  • 失败 3 秒冷却，5 次锁定 300 秒
  • 重启后锁定状态保留
  • 旧 SHA-256 哈希在登录时自动升级
登录相关命令
  • /login <密码> — 登录
  • /register <密码> <确认> — 注册
  • /changepw — 修改密码

  • 封禁历史可追溯，到期自动解封

  • 同 IP 账号可一并查询
功能封禁

03

封禁系统

账号封禁与功能封禁分开，处罚可追溯、可到期自动解除。

账号封禁

  • /linux ban <玩家> — 永久封禁
  • /linux tempban <玩家> <时长> — 临时封禁
  • /linux banip <IP> — IP 封禁
  • /linux unban / unbanip — 解封
时间格式
  • 1d — 1 天
  • 12h — 12 小时
  • 30m — 30 分钟
  • 可组合，如 1d12h
功能封禁
命令封禁内容解封
/linux banmsg禁言 —— 无法发送聊天/linux unbanmsg
/linux banmove禁止移动/linux unbanmove
/linux banblock禁用方块交互/linux unbanblock
/linux banall全面封禁（以上全部）/linux unbanall
历史查询

/linux history <玩家> 可查询该玩家的完整封禁记录， 包含操作人、时间、原因与到期时间。

04

举报系统 NEW

玩家提交举报，插件按被举报人身份自动决定通知谁，处理结果回执给举报人。

提交流程

  • 玩家提交 /linux report <玩家> <原因>
  • 提交后 24 小时冷却，期间不接受重复举报
  • 智能分流：根据被举报人身份决定通知对象
  • 处理并通知：接受或驳回，举报人收到结果
分流规则
  • 被举报普通玩家 → 通知在线协管与管理员
  • 被举报协管 → 直接通知服主
  • 服主 → 同步所有处理结果
  • 服主上线 10 秒后自动推送待处理举报

离线消息缓存与批量清理

玩家离线期间的举报处理结果也会缓存，上线后自动推送。 缓存上限 100 条，超出丢弃最早的。

  • /linux report list — 查看待处理举报
  • /linux report info <编号> — 查看详情
  • /linux report clear — 批量清理已处理举报
为什么要有冷却

防止有人连点刷屏占用管理资源。 24 小时内对同一玩家只能提交一次， 处理完才能再次提交。

05

协管权限体系

协管能做事，但做不了过头的事 —— 权限边界由插件强制，不靠自觉。

协管可用

  • 禁言 / 禁移动 / 禁交互 / 全面封禁
  • 以及 4 个对应的解封命令
  • 处理举报（查看 / 接受 / 驳回）
  • 查询玩家资料与封禁历史

协管不可用

  • 不能账号封禁、不能 IP 封禁
  • 不能清空举报记录
  • 不能重载配置、不能看审计日志
  • 时长必须写明，最长 7 天
界面分流

帮助菜单会按身份展示不同目录：协管看不到自己不能用的命令， 普通玩家只看得到自己的命令。这样不需要额外培训，看菜单就知道能做什么。

07

技术亮点

密码怎么存、缓存怎么做、并发怎么处理 —— 这几个地方决定了插件能不能长期跑。

🔒 安全

  • PBKDF2-HMAC-SHA256 · 12 万次迭代
  • 旧 SHA-256 哈希在登录时自动升级
  • 常量时间比较，防时序攻击
  • 聊天栏输密码，服务端日志零痕迹
  • 防爆破：冷却 + 锁定 + 持久化
  • 权限节点与身份双重校验
为什么用 PBKDF2

服务器密码库一旦泄露，弱哈希可以被离线暴力破解。 PBKDF2 的 12 万次迭代让每次尝试都要付出计算代价， 大幅提高破解成本。

⚡ 性能 · 🧵 并发 · 🛠️ 健壮

  • 多级缓存（ConcurrentHashMap），避免频繁读盘
  • 脏标记 + 定时批量写盘，减少 I/O 次数
  • 异步处理举报推送与消息缓存
  • 异常不中断主流程，单点失败不影响其它功能
  • 配置缺失项自动补全并写回
写盘策略

每次改动只标记「脏」，由定时任务批量落盘。 这样频繁操作（比如连续封禁）不会每次都触发磁盘写入， 同时重启也不会丢数据。

角色与权限

三级身份，权限逐级放大，每条都有明确边界。

👮

协管

有限管理权限，适合日常巡查。

  • 禁言 / 禁移动 / 禁交互 / 全面封禁
  • 处理举报（查看 / 接受 / 驳回）
  • 必须写明时长，最长 7 天
  • 不能账号封禁、不能清空举报
🛡️

管理员（非服主）

完整处罚权限，但摸不到配置与审计。

  • 账号封禁 / 临时封禁 / IP 封禁 / 解封
  • 查询玩家资料、封禁历史、同 IP 账号
  • 处理并清理举报
  • 不能重载配置、不能看审计日志
👑

服主（Linux）

全部权限，包括配置与审计。

  • 以上全部权限
  • 重载配置
  • 查看审计日志与状态总览
  • 清空举报记录
