1快速开始

3 步完成安装，5 分钟即可上手。适用于 Minecraft 1.12.2（Paper / Spigot）。

环境要求

项目 要求
服务端 Paper 或 Spigot 1.12.2
Java Java 8（推荐）或 Java 17/21（需加 --add-opens 参数）
内存 建议 ≥ 2GB
依赖插件 无硬性依赖，可选 XlandCore / 假人插件 / XlandStop

安装步骤

  1. 获取插件 请联系 Linux582021 获取插件文件（QQ：2703441387）。
  2. 放入插件目录 将 InTheNameOfLinux.jar 放入服务器 plugins/ 目录。
  3. 启动服务器 首次启动会生成默认配置，控制台应输出"首次初始化登录密码"。
  4. 登录验证 保护对象（默认 Linux582021）进服后，输入 /linux login，然后在聊天栏发送初始密码 password。
  5. 修改密码 登录成功后，执行 /linux chargepw 新密码 修改密码（至少 6 位）。
⚠️
务必第一时间修改密码 初始密码 password 是明文公开的，未修改前任何人都可以登录。
💡
为什么密码要在聊天栏输入？ 因为 /linux login 密码 这种形式会被服务端日志记录（Minecraft 原生行为）。而聊天栏消息会被插件拦截，控制台和日志完全看不到密码。

3举报系统 NEW

插件内置举报系统，玩家提交举报后，管理层调查处理，结果自动通知当事人与服主。

提交流程

  1. 玩家提交举报 执行 /linux report <玩家> <原因>，提交后进入 1 分钟全局冷却。
  2. 智能分流通知 根据被举报人身份决定通知对象（见下表）。
  3. 24 小时调查冷却 举报提交后 24 小时内不能接受 / 驳回，用于调查。
  4. 管理层处理 管理员 / 协管执行 /linux report accept <ID> 或 reject <ID>，可附加备注。
  5. 结果通知 举报人上线后立即收到处理结果，服主也会收到同步广播。

智能分流规则

被举报人身份通知对象说明
服主（Linux582021）仅服主本人不会广播给其他管理层
协管 / 管理员 / 副服主其他管理层不会通知被举报人本人
普通玩家所有管理层举报人自己除外

离线消息缓存

  • 服主离线时收到新举报 → 消息暂存到 reports.yml。
  • 服主上线 10 秒后自动推送所有暂存消息。
  • 暂存上限 100 条，超出丢弃最早的。
  • 举报人离线期间的处理结果也会缓存，上线后延迟 3 秒推送。

清理举报记录

支持多种清理模式，全部需要二次确认。

/linux report clear handled # 清空已处理的举报
/linux report clear all # 清空所有举报（不可恢复）
/linux report clear pending # 清空待广播消息
/linux report clear player Steve # 清空某玩家相关举报
/linux report clear id 3 # 删除指定举报
/linux report clear confirm # 确认执行（5 分钟内有效）
⚠️
清空操作需二次确认 输入 /linux report clear <模式> 后，需要再执行 /linux report clear confirm 才会真正清空。 确认有效期 5 分钟，过期自动取消。
💡
控制台无需二次确认 如果从控制台执行清空命令，会直接执行，不经过 confirm 步骤。

4二次确认机制 NEW

为了防止误操作，以下命令都需要二次确认才能执行。确认有效期统一为 5 分钟。

操作第一步第二步（确认）
清空玩家历史 /linux clearhistory Steve /linux clearhistory confirm
清空已处理举报 /linux report clear handled /linux report clear confirm
清空全部举报 /linux report clear all /linux report clear confirm
清空待广播消息 /linux report clear pending /linux report clear confirm
清空玩家相关举报 /linux report clear player Steve /linux report clear confirm
删除指定举报 /linux report clear id 3 /linux report clear confirm

确认机制规则

  • 第一步输入后，插件会显示"确认要清空 XXX 吗？"并给出 confirm 提示。
  • 玩家需要在 5 分钟内执行 confirm，过期自动取消。
  • 如果重复执行第一步，上一次待确认操作会被替换（会显示提示）。
  • 玩家退出游戏时，待确认状态会被清除。
  • 控制台执行时无需二次确认，直接生效。
  • 清空待广播消息（pending）时，如果当前没有待广播消息，会提示无需清空。
🚨
清空操作不可恢复 尤其是 /linux report clear all 会删除全部举报记录，请谨慎使用。

inthenameoflinux.ban使用 /ban /xlban /banlistOP
inthenameoflinux.tempban使用 /tempbanOP
inthenameoflinux.banip使用 /banipOP

inthenameoflinux.report.admin清空举报记录（clear 系列命令）OP

协管说明

  • 协管身份优先从 XlandCore 读取（身份 = "协管"，且需确实持有 xlcore.mod）。
  • 如果 XlandCore 未加载，则回退到权限节点 inthenameoflinux.moderator。
  • 协管可用 8 个功能封禁命令，不能使用账号封禁（/ban、/tempban、/banip）。
  • 协管可以查看 / 处理举报（list / info / accept / reject），但不能清空举报（需要 report.admin）。
  • 协管封禁时长上限为 7 天，不能执行永久封禁；/tempban 也受同一上限约束（26.11.2 起补齐）。
  • 协管的帮助菜单和 TAB 补全只显示可用命令。
💡
OP 优先原则 如果玩家同时是 OP 和协管，插件会将其识别为"完整管理员"，显示完整帮助。

7插件联动

XlandCore

用于读取玩家身份（服主 / 副服主 / 管理员 / 协管）。协管体系依赖此插件。

  • 如果 XlandCore 在服务器启动时已加载，静态块会立即检测到。
  • 如果 XlandCore 后加载，插件会在 20 秒后延迟检测一次。
  • 执行 /linux reload 也会重新检测。

假人插件（FakePlayerPlugin）

同步假人数据，用于 /linux fp 和查询识别。

⚠️
如果假人插件改过包名 请在 config.yml 修改 fakeplayer.info-class 的值。

PlaceholderAPI 变量

装好 PlaceholderAPI 后，插件会注册 inl 前缀的变量，可在计分板 / 聊天 / Tab 插件里直接用：

变量说明
%inl_identity%身份（服主 / 副服主 / 管理员 / 协管 / 普通玩家）
%inl_banned%该玩家是否被账号封禁（是 / 否）
%inl_penalty%该玩家是否有任意功能封禁（是 / 否）
%inl_penalty_types%功能封禁类型，逗号分隔（如 禁言,禁用方块）
%inl_playtime%累计在线（如 3天2小时）
%inl_playtime_millis%累计在线（毫秒，便于排序或条件判断）
%inl_bans%全服封禁记录总数
%inl_reports%待处理举报数
%inl_online%在线人数
%inl_fakeplayers%假人数量
%inl_version%插件版本
%inl_fs1%fs1 提权通道是否开启（开 / 关）

没装 PlaceholderAPI 时插件会安静跳过注册，不影响其他功能。可用变量清单也可以直接用 /linux logs 查看。

💡
分页显示 /linux logs、/linux audit、/linux help、/banlist 都是每页 10 行、带可点击的「◀ 上一页 / 下一页 ▶」；玩家点一下即可翻页，控制台会显示纯文字页码提示。

全部在 plugins/InTheNameOfLinux/，可用 /linux logs 一次看到记录数与落盘状态：

XlandStop

监听 xstop / xlstop / xlandstop 命令，全服广播谁在重启服务器。

  • 插件启动时延迟 20 秒检测这三个命令是否注册。
  • 如果检测到，会注册监听器全服广播重启操作。
  • 执行 /linux reload 会重新检测。

8故障排查

问题：登录后仍然无法执行命令

  • 确认输对了密码（大小写敏感）。
  • 如果被锁定，等待锁定时间结束（默认 300 秒）。
  • 查看控制台是否输出"验证身份成功"。

问题：封禁命令没有生效

  • 检查是否拥有对应权限（/linux op 检查自己身份）。
  • 检查 config.yml 里的 refuse-enabled 是否为 true。
  • 查看控制台是否有错误堆栈。

问题：举报提交后无法立即处理

💡
这是设计行为，不是故障 举报提交后 24 小时内不能处理，用于给管理层留出调查时间。等待冷却结束后即可 accept / reject。

问题：服主离线时举报消息没收到

  • 消息会暂存到 reports.yml 的 pending 列表。
  • 服主上线后 10 秒才会推送，请稍等。
  • 如果延迟期间服主又掉线，消息会保留，下次上线继续推送。
  • 如果长时间未收到，检查 reports.yml 的 pending-reports 字段。

问题：清空命令执行后没反应

  • 清空命令需要二次确认。先执行第一步，再执行 confirm。
  • 检查确认是否过期（5 分钟有效期）。
  • 如果是控制台执行，则无需确认，直接生效。
  • 如果提示"没有待确认的清空操作"，说明第一步没有执行或被替换。

问题：ProtocolLib 报错 "Unable to make protected final java.lang.Class..."

💡
这是 ProtocolLib 与 Java 17+ 的兼容问题，与本插件无关。 在启动脚本的 java 命令中加参数： --add-opens java.base/java.lang=ALL-UNNAMED

问题：假人插件显示"版本不兼容"

  • 插件会先用假人插件自己的类加载器加载 fakeplayer.info-class，失败时自动改用实际取到的假人类，所以一般不需要手改。
  • 如果仍然报错，检查假人插件的 FakePlayerInfo 类是否还存在、方法名是否改过。
  • 必要时修改 config.yml 的 fakeplayer.info-class（默认 example.fakeplayer.FakePlayerInfo）。
  • 改完执行 /linux reload。

问题：重启后临时封禁没有恢复 / 到解封时间了还没解封

  • 临时封禁的到期时间是写在 data.yml 里的，重启后插件会自动重建到期任务和"即将解封"提醒任务，无需手动处理。
  • 检查 data.yml 是否损坏（YAML 格式）。
  • 检查服务器时间是否准确（时间错乱会导致到期判断错误）。
  • 到期时间若已被手工改成非法值（例如 2026-02-30），插件会跳过该条并打告警，请检查控制台日志。

问题：封禁记录里一直留着一条"临时"封禁

💡
26.11.2 起会自动清理 临时封禁到期自动解封时，会同时删除 data.yml 里那条记录，/banlist 不会再有幽灵条目。 升级前遗留的过期记录会在下次启动时自动清理一次。

问题：/linux reload 后功能失效

  • 检查控制台是否有异常堆栈。
  • 尝试完全重启服务器（而非 /reload）。
  • 如果仍然异常，删除 plugins/InTheNameOfLinux/ 下的缓存文件（保留 config.yml）。

9常见问题

为什么密码要在聊天栏输入，不能直接 /linux login 密码？
Minecraft 服务端在处理命令前，会先把 /linux login 密码 整条命令写进日志。 而聊天栏消息可以被插件"提前拦截"，不会进入日志。 为了密码安全，本插件采用聊天栏输入方式。
忘记密码了怎么办？
两种方法：
  • 方法一：编辑 config.yml，把 login.password-salt 和 login.password-hash 两行改成 ""（空字符串），重启服务器后密码重置为 password。
  • 方法二：删除整个 config.yml，重启后会自动生成新配置。
举报系统是怎么通知管理层的？
插件会根据被举报人身份智能分流：
  • 被举报人是服主：只通知服主本人。
  • 被举报人是协管 / 管理员 / 副服主：通知其他管理层，不通知被举报人。
  • 被举报人是普通玩家：通知所有管理层（举报人除外）。
如果服主离线，消息会被暂存，上线 10 秒后自动推送。
为什么举报提交后 24 小时内不能处理？
这是调查冷却期，给管理层留出充足时间核实举报内容。 如果举报提交后立刻就能 accept / reject，可能会被恶意利用（例如报复性举报、快速驳回掩盖问题）。 冷却期可确保处理决策是经过调查的。
二次确认过期了怎么办？
直接重新执行第一步命令即可。确认有效期是 5 分钟，过期后旧的待确认状态会被自动清除， 再次执行第一步会生成新的待确认状态。
协管为什么不能封禁账号？
这是设计选择。协管权限有限，只能使用"功能封禁"（禁方块 / 禁移动 / 禁言 / 全封）。 账号封禁（/ban、/tempban、/banip）属于更高级的操作，仅限完整管理员。
协管为什么不能永久封禁？
防止协管滥用权限。永久封禁是不可逆操作，需要完整管理员执行。 协管最长可封 7 天（可配置）。
封禁后玩家还能上线吗？
  • 账号封禁：直接踢出，登录时被拒绝。
  • 功能封禁（禁方块 / 禁移动 / 禁言）：可以正常登录，但对应功能被限制。
为什么被禁言后，我说话没反应？
这是正常的。禁言会拦截你的所有聊天消息、私聊指令、/say 等。你只能与管理员私聊。 屏幕上会显示一条提示"你已被禁言！"。
/linux login 后没有提示我输密码？
检查几点：
  • 你是否是保护对象（默认 Linux582021）？
  • 聊天栏有没有显示黄色提示"请在聊天栏直接输入密码"？
  • 如果提示出现后你退出了游戏，再次进服需要重新输入 /linux login。
数据文件在哪里？如何备份？
所有数据都在 plugins/InTheNameOfLinux/ 目录下：
  • config.yml — 插件配置
  • data.yml — 封禁历史
  • penalty.yml — 功能封禁记录
  • userip.yml — IP 与身份缓存
  • playtime.yml — 游玩时长
  • fp.yml — 假人数据快照
  • reports.yml — 举报记录与待广播消息
直接复制整个文件夹即可备份。
插件会影响服务器性能吗？
影响极小。插件采用了多重优化：
  • 所有数据都缓存到内存，避免频繁读磁盘。
  • 封禁缓存 3 秒，重复查询不重建。
  • 数据文件批量保存（默认 30 秒一次）。
  • 举报待广播消息 5 分钟定时写盘。
  • 异步事件只读判断，回主线程处理。
  • 反射方法首次调用后缓存。
实测 TPS 影响 < 0.5%。
如何修改封禁广播的范围？
编辑 config.yml 里的 broadcast-ban：
  • true（默认）：全服广播。
  • false：只广播给有权限的管理员。
修改后 /linux reload 生效。
如何关闭"突破 fs1 拦截"功能？
两种方法：
  • 执行 /linux fs off（仅 Linux582021 本人可用）。
  • 编辑 config.yml，把 fs1-refuse-enabled 改成 false。
能同时封禁多个玩家吗？
目前不支持批量命令。可以写循环脚本调用 /ban。 批量封禁时，插件会立即写盘（不受 30 秒批量保存影响）。
玩家改名后历史记录会丢失吗？
  • 正版服务器：UUID 不变，改名后历史记录仍在（用 UUID 关联）。
  • 离线服务器：UUID 由名字计算，改名 = 换人，历史记录不会关联。
帮助菜单和封禁列表的翻页怎么用？
两种方式：
  • 在聊天栏点击底部的 ◀ 上一页 / 下一页 ▶ 文字即可翻页。
  • 直接输入 /linux help <页码> 或 /banlist <页码>。
命令条目本身也可以点击：带 <参数> 的命令会自动填充到聊天框，无参数的命令会直接执行。

10卸载与备份

备份

  1. 停止服务器（stop）。
  2. 复制 plugins/InTheNameOfLinux/ 整个目录到安全位置。
  3. 如果使用了协管功能，同时备份 XlandCore 的配置文件。

卸载

  1. 停止服务器。
  2. 删除 plugins/InTheNameOfLinux.jar。
  3. 可选：删除 plugins/InTheNameOfLinux/ 目录（保留则下次安装时数据仍存在）。
  4. 启动服务器。
🚨
卸载前请注意 如果插件中存在活跃的临时封禁任务，卸载后这些任务会被取消，被封禁的玩家将立刻可以进入服务器。 卸载前建议先手动解封所有玩家。
✅
更新插件时 直接替换 jar 文件即可，不需要删除数据目录。配置和数据会自动保留。
