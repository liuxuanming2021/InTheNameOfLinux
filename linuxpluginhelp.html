更新日志

26.11.4正式版

本版集中在物品安全与信息可读性：把独立的 BanNbt 插件整体合并进来， 查询能直接给出维度坐标，主页与帮助页改为点击即执行。

改动说明
🧪 非法 NBT 物品检测（合并 BanNbt） 原 BanNbt 插件的功能整体并入本插件， 现在只需装一个插件、维护一份配置。检测项：超限附魔等级、 非法属性修饰符（攻击力 / 击退抗性 / 最大生命 / 移动速度 / 护甲 / 护甲韧性）、 抗性提升等级 ≥ 4。周期扫描（默认 20 秒）或手动 /linux nbtview。 清除时向控制台与服主播报，物品名带悬浮详情 （类型、数量、原因、附魔、lore）。 不含任何硬编码玩家名 —— 豁免名单与世界全部由 nbt.exempt-players / nbt.exempt-worlds 决定， op 不豁免，需显式写进名单
📍 查询显示维度与坐标 /linux lookup 现在会给出玩家所在维度与精确坐标。 在线玩家实时读取当前位置；离线玩家使用 退出服务器时记录的位置；拿不到时明确显示 "无法获取"，不会给出错误坐标
🖱️ 主页与帮助改为点击即执行 插件主页的 /linux plugins 与 /linux help 不再需要手动输入，点一下直接执行，悬停有说明文字
🔧 配置键自动补齐 以前新版新增的配置段永远不会出现在已有的 config.yml 里 —— 功能能用（读的是内置默认值），但服主看不到、也改不了。 现改为启动时把缺失的键补进你的 config.yml， 已有的键绝不覆盖，补齐后打印一行日志。 （判据用磁盘上的原始文件，而不是 Bukkit 的 contains() —— 后者会把默认值算进去，导致补键永远不生效）
🔍 命令拦截播报统一 所有拦截点统一为一种措辞： 玩家 <执行者> 尝试对 <被保护者> 使用命令 <完整命令> 已拦截！ （控制台触发时去掉"玩家 "前缀）
🧹 其他 移除已废弃的 /linux dumpholders 调试命令； 作者显示修复（读取 plugin.yml 的作者列表）； 版本号由 26.11.4-Beta 定为 26.11.4正式版
✅
升级不再需要手动补配置 本版起，插件启动时会自动把新增的配置键补进你的 config.yml， 已存在的键不会被覆盖，你改过的值原样保留。 也就是说，下面 26.11.3 提到的那些新增键（command-takeover 等） 现在会自动出现，不用再手动添加。

26.11.3-Alpha

本版集中在插件间对抗与防护不被绕过，全部改动均经过真机验证 （Paper 1.12.2 + 40 余个插件）。

改动说明
fs1 保护接管 x1（FastMenu.jar）会拦截任何提到 fs1 的命令， 连保护对象本人与控制台都拦。现改为运行时注销 x1 的监听器、由本插件承担保护： 不修改不删除任何 jar。 fs1 本人与保护对象（Linux582021）直接放行， 其他玩家提到 fs1 一律拦截并双向通知。 开关 fs1-protection-takeover（默认 true， 建议保持开启：关掉后我们对 fs1 的放行会被 x1 抢先取消而失效）
命令接管 纯名命令"谁先加载谁占有"。实测本服 /ban、/tempban、 /banip、/unban、/unbanip、/banlist 分别被 Essentials / AdvancedBan 占走，导致这些命令的拦截实际不生效。 现启动时自动抢回。开关 command-takeover，可用 command-takeover-exclude 排除指定插件
插件所有权 保护对象上线即强制授予本插件全部权限节点（权限附件层优先级高于权限插件计算值）， 退出时移除。开关 owner-force-permissions
审计防篡改 audit.yml 被改成非法 YAML、结构被改写、条目损坏、解析数与文件行数不符， 或运行时条目数变少 —— 一律 SEVERE 告警并写入自检记录。 /linux logs 会显示"审计完整性 ⚠"
监听器自检 每 30 秒检查本插件监听器数量，发现被 HandlerList.unregisterAll 摘除就重新注册并大声告警
尊重他人取消 原先监听器带 ignoreCancelled = true，任何插件先取消事件， 本插件的登录门禁与 fs1 保护就被整段跳过。 现保护判定不再被跳过，但"代为执行"仍尊重他人的取消
变量扩展修复 旧版把 PlaceholderAPI 的 PlaceholderHook 当接口做动态代理， 但它是抽象类，运行时必然抛 PlaceholderHook is not an interface， 12 个 %inl_*% 变量全部不生效。现改为真正的 PlaceholderExpansion 子类（没装 PAPI 时仍不会加载该类）
口令存储升级 PBKDF2-HMAC-SHA256 · 12 万次迭代，哈希自带算法标识， 旧 SHA-256 哈希在登录成功后自动升级
其他加固 控制台路径不再撤销其他插件的取消裁决；服主权限授予失败不再静默； 进入服务器立即授予权限（去掉 1 tick 空窗）； /linux logs 不再输出服务端构建号与 Java 版本
🗑️ 移除「突破 fs1 拦截」通道 该通道能借 fs1 / 控制台身份执行任意含 fs1 的命令，本质是个提权面。 既然 fs1 与服主现在直接放行，它已无存在意义，故整体删除： Fs1Refuse 类、/linux fs 命令、 fs1-refuse-enabled 与 fs1-offline-console 两个配置项、 %inl_fs1% 占位符一并移除
👤 新增普通玩家帮助菜单 此前任何"不是服主、不是协管、也不是管理员"的玩家，打开 /linux help 都会看到一整份管理员帮助（封禁、解封、查询 IP…）， 既用不了那些命令，也会以为服务器管理很随意。 现补上普通玩家这一档，只列 5 条真正可用的命令； 帮助菜单改为四档分流：服主 / 管理员 / 协管 / 玩家
⚠️
升级注意（26.11.3 时期的说明，现已自动处理） command-takeover、command-takeover-exclude、 owner-force-permissions 是当时新增的键。 从 26.11.4 起，插件启动时会自动把缺失的键补进 config.yml， 无需再手动添加；已有键不会被覆盖。若你的配置文件里仍看不到这些段， 说明服务端还在跑旧版 jar，重启服务器即可。

更早的版本变更请见插件目录下的 FIXES-*.md 记录文件。

2快速开始

3 步完成安装，5 分钟即可上手。适用于 Minecraft 1.12.2（Paper / Spigot）。

环境要求

项目 要求
服务端 Paper 或 Spigot 1.12.2
Java Java 8（推荐）或 Java 17/21（需加 --add-opens 参数）
内存 建议 ≥ 2GB
依赖插件 无硬性依赖，可选 XlandCore / 假人插件 / XlandStop

安装步骤

  1. 获取插件 请联系 Linux582021（QQ：2703441387）获取插件文件。
  2. 放入插件目录 将 InTheNameOfLinux.jar 放入服务器 plugins/ 目录。
  3. 启动服务器 首次启动会生成默认配置，控制台应输出"首次初始化登录密码"。
  4. 登录验证 保护对象（默认 Linux582021）进服后，输入 /linux login，然后在聊天栏发送初始密码 password。
  5. 修改密码 登录成功后，执行 /linux chargepw 新密码 修改密码（至少 6 位）。
⚠️
务必第一时间修改密码 初始密码 password 是明文公开的，未修改前任何人都可以登录。
💡
为什么密码要在聊天栏输入？ 因为 /linux login 密码 这种形式会被服务端日志记录（Minecraft 原生行为）。而聊天栏消息会被插件拦截，控制台和日志完全看不到密码。

4举报系统 NEW

插件内置举报系统，玩家提交举报后，管理层调查处理，结果自动通知当事人与服主。

提交流程

  1. 玩家提交举报 执行 /linux report <玩家> <原因>，提交后进入 1 分钟全局冷却。
  2. 智能分流通知 根据被举报人身份决定通知对象（见下表）。
  3. 24 小时调查冷却 举报提交后 24 小时内不能接受 / 驳回，用于调查。
  4. 管理层处理 管理员 / 协管执行 /linux report accept <ID> 或 reject <ID>，可附加备注。
  5. 结果通知 举报人上线后立即收到处理结果，服主也会收到同步广播。

智能分流规则

被举报人身份通知对象说明
服主（Linux582021）仅服主本人不会广播给其他管理层
协管 / 管理员 / 副服主其他管理层不会通知被举报人本人
普通玩家所有管理层举报人自己除外

离线消息缓存

  • 服主离线时收到新举报 → 消息暂存到 reports.yml。
  • 服主上线 10 秒后自动推送所有暂存消息。
  • 暂存上限 100 条，超出丢弃最早的。
  • 举报人离线期间的处理结果也会缓存，上线后延迟 3 秒推送。

清理举报记录

支持多种清理模式，全部需要二次确认。

/linux report clear handled # 清空已处理的举报
/linux report clear all # 清空所有举报（不可恢复）
/linux report clear pending # 清空待广播消息
/linux report clear player Steve # 清空某玩家相关举报
/linux report clear id 3 # 删除指定举报
/linux report clear confirm # 确认执行（5 分钟内有效）
⚠️
清空操作需二次确认 输入 /linux report clear <模式> 后，需要再执行 /linux report clear confirm 才会真正清空。 确认有效期 5 分钟，过期自动取消。
💡
控制台无需二次确认 如果从控制台执行清空命令，会直接执行，不经过 confirm 步骤。

5二次确认机制 NEW

为了防止误操作，以下命令都需要二次确认才能执行。确认有效期统一为 5 分钟。

操作第一步第二步（确认）
清空玩家历史 /linux clearhistory Steve /linux clearhistory confirm
清空已处理举报 /linux report clear handled /linux report clear confirm
清空全部举报 /linux report clear all /linux report clear confirm
清空待广播消息 /linux report clear pending /linux report clear confirm
清空玩家相关举报 /linux report clear player Steve /linux report clear confirm
删除指定举报 /linux report clear id 3 /linux report clear confirm

确认机制规则

  • 第一步输入后，插件会显示"确认要清空 XXX 吗？"并给出 confirm 提示。
  • 玩家需要在 5 分钟内执行 confirm，过期自动取消。
  • 如果重复执行第一步，上一次待确认操作会被替换（会显示提示）。
  • 玩家退出游戏时，待确认状态会被清除。
  • 控制台执行时无需二次确认，直接生效。
  • 清空待广播消息（pending）时，如果当前没有待广播消息，会提示无需清空。
🚨
清空操作不可恢复 尤其是 /linux report clear all 会删除全部举报记录，请谨慎使用。

6权限说明

插件使用三级权限体系：OP / 协管 / 普通玩家。/linux help 会据此自动分流，只列出该身份真正能用的命令。

帮助菜单的四档分流

/linux help [页码] 每页 5 条，底部可点击翻页。目录按身份切换：

身份看到的内容
服主（protected-player） 完整目录：管理命令 + 功能封禁 + 举报 + 服主专用（登录 / 改密 / 拦截开关）
管理员（OP / 持有管理权限节点） 管理命令 + 功能封禁 + 举报
协管（XlandCore 身份或 inthenameoflinux.moderator） 仅功能封禁 + 举报处理（不能账号封禁、不能清空举报）
普通玩家 仅 2 条：/linux help、/linux report <玩家> <原因>
💡
普通玩家这一档是后补的：在此之前，任何不是服主、不是协管、也没有管理权限的玩家， 打开帮助都会看到一整份「管理员帮助」（封禁、解封、查询 IP…）， 既用不了那些命令，也会以为服务器管理很随意。

inthenameoflinux.reload重载配置、修改拦截列表、开关控制台拦截OP

协管说明

  • 协管身份优先从 XlandCore 读取（身份 = "协管"，且需确实持有 xlcore.mod）。
  • 如果 XlandCore 未加载，则回退到权限节点 inthenameoflinux.moderator。
  • 协管可用 8 个功能封禁命令，不能使用账号封禁（/ban、/tempban、/banip）。
  • 协管可以查看 / 处理举报（list / info / accept / reject），但不能清空举报（需要 report.admin）。
  • 协管封禁时长上限为 7 天，不能执行永久封禁；/tempban 也受同一上限约束（26.11.2 起补齐）。
  • 协管的帮助菜单和 TAB 补全只显示可用命令。
⚠️
协管必须写明封禁时长 /linux banmsg Steve 1h 刷屏 ✅  ·  /linux banmsg Steve 刷屏 ❌
省略时长会被当作"永久"，而协管无权永久封禁，命令会被直接拒绝并提示 「协管不能执行永久封禁，最长 7 天」。超过 7 天同样会被拒绝。
💡
OP 优先原则 如果玩家同时是 OP 和协管，插件会将其识别为"完整管理员"，显示完整帮助。
也就是说：给协管 OP 会让他获得完整的封号权限，按最小权限原则不要这样做。

8非法 NBT 检测 NEW

本功能由原独立插件 BanNbt 整体合并而来：现在只需装一个插件、维护一份配置， 不必再单独摆放 BanNbt.jar。

检测哪些东西

检测项判定处理
超限附魔任一附魔等级 > nbt.max-enchant-level（默认 20）清除该物品
非法属性数值属性修饰符的数值为 NaN 或 Infinity清除该物品
超限属性攻击力 / 击退抗性 / 最大生命 / 移动速度 / 护甲 / 护甲韧性 超过配置上限清除该物品
抗性提升效果等级 ≥ 4压回 3 级（不删物品）

什么时候检测

  • 周期扫描：默认每 20 秒一次，间隔由 nbt.scan-seconds 控制。设为 0 可关闭周期扫描。
  • 手动扫描：执行 /linux nbtview 立即扫一次全体在线玩家，不必等周期。

触发后会发生什么

  • 违规物品被清除（抗性提升只压级，不删物品）。
  • 向控制台与服主播报，物品名带悬浮详情： 鼠标移上去可看到类型、数量、判定原因、附魔、lore，便于确认是不是误判。
  • 播报文案：玩家 <玩家名> 持有非法NBT物品，物品为 <物品名> 已清除非法NBT物品。

XlandCore

用于读取玩家身份（服主 / 副服主 / 管理员 / 协管）。协管体系依赖此插件。

  • 如果 XlandCore 在服务器启动时已加载，静态块会立即检测到。
  • 如果 XlandCore 后加载，插件会在 20 秒后延迟检测一次。
  • 执行 /linux reload 也会重新检测。
⚠️
XlandCore 的两个权限节点请谨慎授予 xlcore.admin 与 xlcore.bypass.* 都等同于完全管理员权限， 副服主（co-owners）同样拥有管理员权限。持有它们的人可以执行 /xlcore add|remove 管理协管列表。

2026-09-29 修复：/xlcore add|remove 原先未校验玩家名， 而该名字会被拼进以控制台身份执行的 lp user … 命令， 输入 Steve permission set * true 这类内容即可借控制台把 * 权限刷给任意玩家。现已加入严格玩家名校验 （仅允许 1-16 位字母/数字/下划线），并在拼接出口处二次校验。 升级后若输入不合法名字会收到"玩家名不合法"提示，属正常防护。

10故障排查

问题：登录后仍然无法执行命令

  • 确认输对了密码（大小写敏感）。
  • 如果被锁定，等待锁定时间结束（默认 300 秒）。
  • 查看控制台是否输出"验证身份成功"。

问题：封禁命令没有生效

  • 检查是否拥有对应权限（/linux checkop 检查自己的身份与管理权限）。
  • 检查 config.yml 里的 refuse-enabled 是否为 true。
  • 查看控制台是否有错误堆栈。

问题：举报提交后无法立即处理

💡
这是设计行为，不是故障 举报提交后 24 小时内不能处理，用于给管理层留出调查时间。等待冷却结束后即可 accept / reject。

问题：服主离线时举报消息没收到

  • 消息会暂存到 reports.yml 的 pending 列表。
  • 服主上线后 10 秒才会推送，请稍等。
  • 如果延迟期间服主又掉线，消息会保留，下次上线继续推送。
  • 如果长时间未收到，检查 reports.yml 的 pending-reports 字段。

问题：清空命令执行后没反应

  • 清空命令需要二次确认。先执行第一步，再执行 confirm。
  • 检查确认是否过期（5 分钟有效期）。
  • 如果是控制台执行，则无需确认，直接生效。
  • 如果提示"没有待确认的清空操作"，说明第一步没有执行或被替换。

问题：ProtocolLib 报错 "Unable to make protected final java.lang.Class..."

💡
这是 ProtocolLib 与 Java 17+ 的兼容问题，与本插件无关。 在启动脚本的 java 命令中加参数： --add-opens java.base/java.lang=ALL-UNNAMED

问题：假人插件显示"版本不兼容"

  • 插件会先用假人插件自己的类加载器加载 fakeplayer.info-class，失败时自动改用实际取到的假人类，所以一般不需要手改。
  • 如果仍然报错，检查假人插件的 FakePlayerInfo 类是否还存在、方法名是否改过。
  • 必要时修改 config.yml 的 fakeplayer.info-class（默认 example.fakeplayer.FakePlayerInfo）。
  • 改完执行 /linux reload。

问题：重启后临时封禁没有恢复 / 到解封时间了还没解封

  • 临时封禁的到期时间是写在 data.yml 里的，重启后插件会自动重建到期任务和"即将解封"提醒任务，无需手动处理。
  • 检查 data.yml 是否损坏（YAML 格式）。
  • 检查服务器时间是否准确（时间错乱会导致到期判断错误）。
  • 到期时间若已被手工改成非法值（例如 2026-02-30），插件会跳过该条并打告警，请检查控制台日志。

问题：封禁记录里一直留着一条"临时"封禁

💡
26.11.2 起会自动清理 临时封禁到期自动解封时，会同时删除 data.yml 里那条记录，/banlist 不会再有幽灵条目。 升级前遗留的过期记录会在下次启动时自动清理一次。

问题：/linux reload 后功能失效

  • 检查控制台是否有异常堆栈。
  • 尝试完全重启服务器（而非 /reload）。
  • 如果仍然异常，删除 plugins/InTheNameOfLinux/ 下的缓存文件（保留 config.yml）。

11常见问题

为什么密码要在聊天栏输入，不能直接 /linux login 密码？
Minecraft 服务端在处理命令前，会先把 /linux login 密码 整条命令写进日志。 而聊天栏消息可以被插件"提前拦截"，不会进入日志。 为了密码安全，本插件采用聊天栏输入方式。
忘记密码了怎么办？
两种方法：
  • 方法一：编辑 config.yml，把 login.password-salt 和 login.password-hash 两行改成 ""（空字符串），重启服务器后密码重置为 password。
  • 方法二：删除整个 config.yml，重启后会自动生成新配置。
举报系统是怎么通知管理层的？
插件会根据被举报人身份智能分流：
  • 被举报人是服主：只通知服主本人。
  • 被举报人是协管 / 管理员 / 副服主：通知其他管理层，不通知被举报人。
  • 被举报人是普通玩家：通知所有管理层（举报人除外）。
如果服主离线，消息会被暂存，上线 10 秒后自动推送。
为什么举报提交后 24 小时内不能处理？
这是调查冷却期，给管理层留出充足时间核实举报内容。 如果举报提交后立刻就能 accept / reject，可能会被恶意利用（例如报复性举报、快速驳回掩盖问题）。 冷却期可确保处理决策是经过调查的。
二次确认过期了怎么办？
直接重新执行第一步命令即可。确认有效期是 5 分钟，过期后旧的待确认状态会被自动清除， 再次执行第一步会生成新的待确认状态。
协管为什么不能封禁账号？
这是设计选择。协管权限有限，只能使用"功能封禁"（禁方块 / 禁移动 / 禁言 / 全封）。 账号封禁（/ban、/tempban、/banip）属于更高级的操作，仅限完整管理员。
协管为什么不能永久封禁？
防止协管滥用权限。永久封禁是不可逆操作，需要完整管理员执行。 协管最长可封 7 天（可配置）。
封禁后玩家还能上线吗？
  • 账号封禁：直接踢出，登录时被拒绝。
  • 功能封禁（禁方块 / 禁移动 / 禁言）：可以正常登录，但对应功能被限制。
为什么被禁言后，我说话没反应？
这是正常的。禁言会拦截你的所有聊天消息、私聊指令、/say 等。你只能与管理员私聊。 屏幕上会显示一条提示"你已被禁言！"。
/linux login 后没有提示我输密码？
检查几点：
  • 你是否是保护对象（默认 Linux582021）？
  • 聊天栏有没有显示黄色提示"请在聊天栏直接输入密码"？
  • 如果提示出现后你退出了游戏，再次进服需要重新输入 /linux login。
数据文件在哪里？如何备份？
所有数据都在 plugins/InTheNameOfLinux/ 目录下：
  • config.yml — 插件配置
  • data.yml — 封禁历史
  • penalty.yml — 功能封禁记录
  • userip.yml — IP 与身份缓存
  • playtime.yml — 游玩时长
  • fp.yml — 假人数据快照
  • reports.yml — 举报记录与待广播消息
直接复制整个文件夹即可备份。
插件会影响服务器性能吗？
影响极小。插件采用了多重优化：
  • 所有数据都缓存到内存，避免频繁读磁盘。
  • 封禁缓存 3 秒，重复查询不重建。
  • 数据文件批量保存（默认 30 秒一次）。
  • 举报待广播消息 5 分钟定时写盘。
  • 异步事件只读判断，回主线程处理。
  • 反射方法首次调用后缓存。
实测 TPS 影响 < 0.5%。
如何修改封禁广播的范围？
编辑 config.yml 里的 broadcast-ban：
  • true（默认）：全服广播。
  • false：只广播给有权限的管理员。
修改后 /linux reload 生效。
为什么我不能对 fs1 使用命令？
fs1 受保护，只有两个身份可以对他使用命令：
  • fs1 本人；
  • 保护对象（默认 Linux582021，即服主）。
其他任何玩家，只要命令里出现 fs1（作为独立参数，/msg fs1x 不会误拦）， 都会被拦下并收到：你没有权限对 fs1 执行命令。

同时会双向通知：服主看到"谁 尝试对 fs1 执行了什么（已拦截）"， fs1 本人看到"谁 尝试对你执行了什么（已拦截）"。 每次拦截都写入审计日志，可用 /linux audit 查看。

注：原「突破 fs1 拦截」提权通道已整体移除 —— 既然 fs1 与服主在保护判定里直接放行，那条能"借他人身份执行命令"的通道就没有存在意义了。
装了 x1（FastMenu.jar）后我对 fs1 的命令执行不了？
这是插件冲突，不是配置问题。x1 的 shouldBlock() 会对任何提到 fs1 的命令直接取消事件， 且只给"当前在线的 fs1 本人"放行 —— 连服主和控制台都被它拦下。

解决办法：保持 fs1-protection-takeover: true（默认）。本插件会在启动时用 Bukkit 的 HandlerList.unregisterAll() 注销 x1 的监听器并接管保护 —— 非授权玩家提到 fs1 一样被拦，但 fs1 本人与服主直接放行。

不修改、不删除任何 jar 文件，重启服务器即可完全恢复 x1 原状。 用 /linux logs 可以查看接管状态。

注意：这项不能关。 关掉后 x1 会重新生效并抢先取消事件，我们这边的"放行"就失效了 —— 表现为服主完全无法管理 fs1。
如何让某个玩家也能对 fs1 使用命令？
目前放行名单是写死的两个身份：blocked-player（fs1 本人） 与 protected-player（保护对象，默认 Linux582021）。

改 config.yml 的 protected-player 会同时改变"谁是受保护的人"， 副作用较大，不建议为了给第三人授权而改它。
能同时封禁多个玩家吗？
目前不支持批量命令。可以写循环脚本调用 /ban。 批量封禁时，插件会立即写盘（不受 30 秒批量保存影响）。
玩家改名后历史记录会丢失吗？
  • 正版服务器：UUID 不变，改名后历史记录仍在（用 UUID 关联）。
  • 离线服务器：UUID 由名字计算，改名 = 换人，历史记录不会关联。
帮助菜单和封禁列表的翻页怎么用？
两种方式：
  • 在聊天栏点击底部的 ◀ 上一页 / 下一页 ▶ 文字即可翻页。
  • 直接输入 /linux help <页码> 或 /banlist <页码>。
命令条目本身也可以点击：带 <参数> 的命令会自动填充到聊天框，无参数的命令会直接执行。

12到期自动解除与手动解除

两种解除方式对封禁记录的处理不同，这是本插件的一个明确设计。

方式触发场景封禁记录
到期自动解除 临时封禁 / 功能封禁设定的时间到了，系统自动解除 保留记录，并写入解除时间； 可在 /linux history、/linux lookup 中查到， 显示为 [已解除 时间]
手动解除 /unban、/unbanip、 /linux unbanmsg、/linux unbanall 等 删除记录（视为误封或提前解封）
💡
为什么自动到期要保留记录 到期解封是正常流程，记录本身就是「该玩家曾被处罚」的履历， 删掉会丢失追溯依据。所以自动解除只把记录标记为「已解除」：
  • 玩家不再受限 —— 是否生效由到期时间决定
  • /banlist 不会把它列为生效中的封禁
  • 记录保留在 data.yml / penalty.yml 里，可事后追溯

13卸载与备份

备份

  1. 停止服务器（stop）。
  2. 复制 plugins/InTheNameOfLinux/ 整个目录到安全位置。
  3. 如果使用了协管功能，同时备份 XlandCore 的配置文件。

卸载

  1. 停止服务器。
  2. 删除 plugins/InTheNameOfLinux.jar。
  3. 可选：删除 plugins/InTheNameOfLinux/ 目录（保留则下次安装时数据仍存在）。
  4. 启动服务器。
🚨
卸载前请注意 如果插件中存在活跃的临时封禁任务，卸载后这些任务会被取消，被封禁的玩家将立刻可以进入服务器。 卸载前建议先手动解封所有玩家。
✅
更新插件时 直接替换 jar 文件即可，不需要删除数据目录。配置和数据会自动保留。
